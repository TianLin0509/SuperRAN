# 默认信道配置：真实 AAU + n41

**什么时候读这一份**：用户问默认配置是什么、为什么是这些数、
或者要拿本项目的数字跟别处的仿真结果对账时。

**不确定用什么配置时，用 `company_64t4r`（单小区）或
`company_64t4r_multicell`（多小区）。** `sr_plan` 已经默认挑它们。

| profile | RF 端口 | 馈电与物理阵子 | RF 垂直间距 |
|---|---|---|---|
| 默认 64T | **8H x 4V x 2pol = 64** | **1 驱 3**，共 **192 AE** | 2.01λ |
| 可选 256T | **16H x 8V x 2pol = 256** | **1 驱 6**，共 **1536 AE** | 4.02λ |

两种 profile 的物理 AE 间距都是水平 **0.5λ**、垂直 **0.67λ**。

## 新模块必须使用的端口布局合同

- `port_order = pol_h_v`
- `vertical_index_order = top_to_bottom`，即 `v=0` 是物理顶部
- 0-based：`r(p,h,v) = p*N_H*N_V + h*N_V + v`
- 64T 1-based：`p*32 + h*4 + v + 1`；锚点为 1、5、33
- 256T 1-based：`p*128 + h*8 + v + 1`；锚点为 1、9、129
- 物理 AE：`e(p,h,v,q) = p*N_H*(N_V*M) + h*(N_V*M) + M*v + q`
- 合同版本：`pol_h_v-top_to_bottom-v1`

历史 64T 是 `h_v_pol + bottom_to_top`。它只允许出现在旧数据读取和显式消融中；
转换必须经过物理行映射并同时置换 `H`、`W`、`F`。只改 shape、只改元数据或只重排
其中一个矩阵都不成立。非均匀子阵校准还必须声明
`calibration_vertical_index_order`，否则换序会把馈电幅相倒置。

| | 默认值 |
|---|---|
| 载波 | n41 **2.6 GHz**、**30 kHz** 子载波间隔、**100 MHz** |
| RB | **272**（17 RBG x 16 RB）。仿真到 RB 为止，不建模到 RE |
| 终端 | **4R** 接收、**下行** |

**这不是可选项，是本地硬件事实。** ChannelHub 的默认 `legacy_64` 把 64 个端口
当成独立阵元、间距一律 0.5λ——那是另一套阵列。面板是 8x4x2 或 16x8x2 时
SuperRAN 会自动切到对应真实模型，`summary.antenna_model` 里能查布局版本。

实测两者的差距（同 seed、单小区、30 样本）：

| | 真实 AAU | legacy_64 |
|---|---|---|
| SVD 谱效 | 28.20 | 33.23 |
| 吞吐均值 | 1055.5 Mbps | 1337.5 Mbps |
| 边缘用户 | 582.4 Mbps | 940.0 Mbps |

这是 2026-07-31 旧内核上的历史消融，仅证明两种阵列不是同一物理模型。
2026-08-11 后大尺度功率参考与链路锚点已重构，27%/61% **不得作为当前通用结论**；
需要引用差值时必须在当前版本用同一批信道重跑配对实验。

两条边界要记住：

- **固定阵列增益与数字 BF 分层。** 阵元方向图、1 驱 N 固定馈电、电下倾与
  垂直几何会进入 conducted-power 链路预算，因此会影响几何 SNR/SIR/SINR；
  数字多端口预编码增益仍在 H 中，只由链路级计算一次。
- **阵元方向图是 3GPP 式参数化模型，不是实测方向图**
  （`element_pattern_is_measured: false`），别说成实测。

272 vs 273：38.104 标准表在 100 MHz/30 kHz 下是 273 RB，272 是按 RBG 对齐
（17x16）取的。两个数口径不同，默认用 272。

1 驱 N 是**具体 AAU 的硬件事实，不是通用规律**：只对 8x4x2（1 驱 3）与
16x8x2（1 驱 6）自动生效；16T 等未知面板保持 legacy，不能按端口数猜馈电。

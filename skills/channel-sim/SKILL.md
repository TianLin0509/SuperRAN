# 无线信道仿真编排

配合 `superwireless` MCP 使用。MCP 提供能力与数据，本 skill 负责和用户一起
把仿真条件定清楚，并留下可复现的记录。

## 核心原则

**永远不要替用户猜关键的仿真条件，也永远不要把几十个参数甩给用户。**

MCP 知道每类任务有哪几个参数一改结论就翻盘。你的职责是把这些问题**用人话**
转述给用户，并把用户的回答翻译回参数。

**数据不进对话。** MCP 返回的是句柄和取货代码，不是信道矩阵。一个样本
可达数百 KB，序列化成文本会膨胀到十几 MB。拿到取货代码后写分析脚本，
不要试图把数组打印出来看。

## 三段式流程

### 第一段 · 收敛式头脑风暴

调 `sw_plan(intent=<用户原话>)`。返回里有两层问题，**顺序不能颠倒**：

调 `sw_plan(intent=<用户原话>)`。**它只返回这一轮该问的 2~4 个问题**，
MCP 自己记着问到哪了，你不用规划轮次。

#### 每轮怎么问

`design_questions` 和 `questions` 合起来就是本轮的全部问题，**照它给的问，
不要自己加**（`also_configurable` 里的不要问，那只是告诉用户边界在哪）。

每个问题：

1. **把选项编号列出来**（3~4 个），带上每个选项的 `note`——说明什么情况下
   选它、有什么代价
2. **标出推荐项**（`recommended: true`）并说一句为什么推荐。给一排平铺的
   选项让用户自己权衡是偷懒，明确推荐才是帮忙
3. **最后留一句"或者你直接说"**（`allow_free`）——选项是启发思路，不是限制

呈现示例：

> **你的方法要跟什么比？**
> ① 3GPP Type I 或 Type II 码本 —— 最常见的基线，几乎所有 CSI 工作都会比它 **← 推荐**
> ② 理想信道的 SVD 预编码 —— 理论天花板，看你离上界差多少
> ③ 某篇已发表方法 —— 告诉我哪篇，我尽量对齐它的实验设置
> ④ 还没定，先看可行性
>
> 或者你直接说。

开放式问"你要跟什么比"，很多人第一反应答不上来；但看到"理想信道的
SVD 上界"就会想起来还有这条路。

#### 轮次怎么推进

用户答完，调 `sw_revise`（仿真参数走 `overrides`，实验设计回答走 `design`），
它返回下一轮该问什么。看两个字段决定要不要继续：

- `has_more_rounds: false` → 问完了，进第二段
- **用户说"随便 / 默认就行 / 就这样"** → 立刻停，别再问

典型是 2~3 轮：第 1 轮实验设计（基线、指标），第 2 轮关键参数（信道模型、
天线这类一改结论就变的），第 3 轮补充确认。**每一轮之后都能直接生成**
（`can_generate_now` 恒为 true），没答的走默认值，生成后 `auto_decided`
会如实列出替用户做的决定。

不要追求把所有问题问完。**问的目的是让结论可靠，不是走完流程。**

#### 每轮还要带上的

- **`suggested_sweeps` 提一句**：很多结论必须靠 A/B 才立得住。一次生成
  两组比事后补跑省事得多。
- **`pitfalls` 挑相关的说一两条**，别全倒出来。
- **`also_configurable` 只报名字**，让用户知道还能调什么，但别展开成问题。

发散式追问在这里是错的——参数空间有限且已知，MCP 手里有完整的合法取值表。
像医生问诊：问题有限、有针对性、每个都有明确用意。

### 第二段 · 计划书

`sw_generate` 会返回 `plan_markdown`：上半是人话（验证什么、每个关键选择及理由），
下半是配置。它已随数据一起存档。

用户想先看再跑时，把它展示出来；用户着急时不必展示，存档即可。

### 第三段 · 执行与取货

调 `sw_deliver(dataset_id, want=<用户的话>)`。`want` 直接写自然语言：
"信道"、"信道 + PMI + SRS RSRP"、"我还想看时延功率谱"。

拿到 `code` 后**写进脚本文件运行**，不要逐行复述给用户。

用户中途改主意要别的测量量时，**重新 deliver 即可，绝对不要重跑仿真**——
所有测量量都是从信道现算的，重新取货是秒级的。

## 蒙特卡洛仿真的标准流程

用户最常见的场景是"我有个算法想法，要在可信的信道上跑蒙特卡洛"。标准做法：

1. **生成后先体检** —— `sw_validate(dataset_id)`。结论建立在信道之上，
   `passed` 为 false 时先修配置。12 项检查里最常触发的是：场景与信道模型
   视距类别不匹配、样本量不足、信噪比分布过窄。
2. **算谱效用 `sw_link_performance`** —— 它同时给出 SVD（理论上界）、宽带 SVD、
   Type I 码本、DFT 波束四种方案，用户的方法应当和这几个在同一批信道上比。
3. **看收敛** —— 返回里 `converged` 为 false 时**必须告诉用户**：
   置信区间没收窄到 5%，方案间的差异可能只是随机波动。加大 `num_samples`
   再跑，报告里会给出大致需要多少样本。
4. **CSI 误差的代价** —— `use_estimated_csi=true` 用估计信道算预编码、
   用理想信道评估性能。这是 CSI 反馈类课题的核心对比。

**别替用户下"A 比 B 好"的结论，除非置信区间已经分开。** 这是蒙特卡洛最常见的错误。

## 必须守住的几条

**体检拦截要当真。** `sw_generate` 返回 `status: "blocked"` 时，说明这个参数
组合跑得出结果但结果没有物理意义（最典型的是波束/定位任务配 TDL 模型——
TDL 没有每条径的角度，算法会输出一堆看似正常的垃圾且不报错）。
把 `message` 和 `suggestion` 转述给用户，等他决定，不要自作主张绕过。

**这里的测量量是物理量，不是训练特征。** PDP 不归一化、带真实时延轴；
RSRP 不做区间截断；SRS 给完整协方差和全部特征值；PMI 给 38.214 Type I 码本
索引和预编码矩阵。如果用户提到 ChannelHub 的 16-token 特征，那是另一套东西
（为 MAE 训练服务、经过门控与归一化），别混用。

**先小后大。** 正式实验前先跑 20 个样本确认流程通，再放大到几百个。
`sw_plan` 的 `estimated.size_mb` 会给体积预估，超过 1 GB 时提醒用户。

**信噪比不能直接设定。** 它由路损、发射功率、撒点位置共同决定。用户要求
特定信噪比区间时会走拒绝采样，可能很慢甚至取不到样本。想整体抬高或压低，
调发射功率或站间距更有效。

## 射线追踪

`sw_list_scenes` 查场景。内置 4 个（慕尼黑、巴黎凯旋门、佛罗伦萨、旧金山）
开箱即用；中国城市 6 个（北京中关村、上海陆家嘴、深圳福田、广州天河、
杭州钱江、重庆解放碑）首次使用自动准备资产。

切场景在 overrides 里写 `{"scene": "shenzhen_futian"}`，或直接用
`rt_munich` / `rt_shanghai_lujiazui` / `rt_shenzhen_futian` 预设。

**射线追踪比统计信道慢一个量级**（约 2~6 秒/样本 vs 0.2 秒）。用户要几百个
样本时先提醒一下耗时，或建议先跑 20 个看看。

**射线追踪数据集不能调 `ds.paths()`**——多径来自真实建筑几何，套用 CDL
标准剖面得到的角度与数据无关。MCP 会直接报错而不是返回错误结果。
用户需要逐径角度时，建议改用 CDL 模型。

典型用法是**先用统计信道快速迭代，定型后换真实地图复核**——两者的取货
代码完全一样，算法代码一行不用改。

## 环境

引擎可用性调 `sw_capabilities` 查。`quadriga_real` 需要 MATLAB/Octave，
未纳入本方案。引擎不可用时如实告诉用户缺什么，不要假装能跑。

## 对话示例

> **用户**：帮我验证一个 CSI 压缩的想法，先弄一批单小区 64T4R 的信道数据。
>
> **你**：（sw_plan → 第 1 轮·实验设计）配好了单小区 64T4R、273 RB、CDL-C、100 MHz。
> 先对齐两件事，这比参数重要——参数配错重跑就行，实验设计错了结论作废。
>
> **① 你的方法要跟什么比？**
> ① 3GPP Type I 或 Type II 码本 —— 最常见的基线 **← 推荐**
> ② 理想信道 SVD 预编码 —— 理论天花板
> ③ 某篇已发表方法 —— 告诉我哪篇，我对齐它的设置
> ④ 还没定，先看可行性
>
> **② 用什么指标？**
> ① 重建精度类：NMSE / 余弦相似度 —— 最直接，只要信道矩阵 **← 推荐**
> ② 系统收益类：频谱效率或吞吐损失 —— 要额外留预编码矩阵和 SINR
> ③ 任务专属：波束命中率 / 定位误差 / BLER
> ④ 还没想好
>
> 或者你直接说。
>
> **用户**：跟 Type II 比，看 NMSE 和频谱效率损失。
>
> **你**：（sw_revise → 第 2 轮·关键参数）记下了。这两个参数一改结论就变：
>
> **① 信道模型？** CDL-C 非视距城区基准 **← 推荐** / CDL-A 强散射（可与 C 对照）/
> CDL-D 视距（注意：视距与否由几何判定，选它不等于得到视距信道）/ TDL-C 无角度
>
> **② 要不要限定信噪比范围？** 不限定 **← 推荐**（自然分布最快）/ 只看边缘 / 只看近点
>
> 另外建议跑两组对比，否则结论站不住：CDL-A vs CDL-C（散射丰富度）、
> 站间距 200m vs 800m（真正改变视距比例的是几何）。
> 还能调：移动速度、导频类型、TDD配比、随机种子……共 20 项。
>
> **用户**：都用推荐的，按你说的对比组跑。
>
> **你**：（sw_revise → has_more_rounds=false → sw_generate ×2 → sw_deliver）
> 两组数据都好了，计划书已存档……

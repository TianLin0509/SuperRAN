# SuperRAN 仿真 Agent 手册

手册修订：2026-09-12。配合 `superran` MCP（35 个 `sr_*` 工具）使用。
仓库 `skills/channel-sim/` 是内容真源；`superran` 是由安装器生成的显式点名入口，
正文与参考文件相同，只有名称和触发范围不同。不得手工维护另一份正文。
安装与校验见仓库 `INSTALL_AGENT.md`；当前能力以工具 schema、配置回显及本次证据为准。

## 先理解人在研究什么

人在意通信机制、实验是否公平、结果为什么如此。先说“我理解为……”复述要回答的
通信问题，并澄清最可能混淆的边界；例如研究调度引起的小包完成时延变化，不等于测峰值谱效。
已明确的条件直接继承。首次使用缩写展开全称，随后用一句白话解释；专家理解后不反复教学。
文件路径、内部工具、数据结构由 Agent 处理，只有它们影响交付或复现时才告诉人。

| 人的任务 | 完成条件 | 路由 |
|---|---|---|
| 理解原理、判断能不能做 | 解释机制与当前边界 | 查能力与资料即可；不强行创建仿真 |
| 要一批数据或一个测量量 | 条件相符、体检通过、文件可读取 | 计划 → 生成 → 体检 → 交付；不问虚构的基线 |
| 先看看机制能否跑通 | 探索性结果、异常与后续判断清楚 | 小规模试点；不得包装成收益结论 |
| 正式比较方案 | 公平比较、预注册主问题、统计判决、物理解释 | 对齐目标 → 生成数据 → 跑对比 → 写结论 |

完整比较的可见进度只用上面四个阶段；工具调用与门禁是内部步骤。
没有比较的任务按其完成条件结束。**“证据不足”也是有效结论**，不能反复补跑直到显著。

## 需求落实成实验约定

开始实跑前读 `references/asking.md` 与 `references/experiment-agreement.md`。
只问会改变通信解释或实验公平性的未决条件，通常一轮不超过三个关键问题。
有依赖就先问上游；能从现有数据、能力、场景查到的事实由 Agent 查。不要机械转发
`round_questions`；工具可能重复询问已答条件，或把“调度”识别成泛化干扰任务。
干扰画像类意图（站距/IoT/干扰水平）会走 `interference_scan`，第一轮先问预期与模型假设。

把问题、研究机制、改变/固定条件、指标口径、合理性检查、预算与结论边界写成一页约定。
每次回答立即更新对应正文；复用已有授权，不额外设置批准仪式。用户说“默认”后停止追问，
公开采用的合理默认；遇到不支持或互相矛盾的关键条件则指出差异，不能悄悄换题。

**约定不是配置已经生效的证明。** 当前草稿的 `design` 主要记录设计文字；系统参数
需要 Agent 单独传给系统工具。生成前逐项比对约定与生成参数，系统运行前再比对各臂参数，
运行后比对实际配置回显。保留原话、参数映射与差异记录，发现偏差先修正或说明阻断。
`ready_to_go` / `can_generate_now` / `next` 只是工具提示，不能代替本手册与实际门禁。

## 执行与证据

<HARD-GATE>
不得在**门 1（信道体检）通过之前**开始跑任何实验或分析。
不得在**门 3（结论检验）通过之前**说出任何"A 比 B 好 / 提升了 X%"式的判断。

过不了门时，如实说明拦在哪一项，让用户决定是修还是接受局限。**不要绕过：**

- 不许用"总体来看""趋势上""大部分样本呈现正向""量级上"把没过的门糊过去；
  也不许把"不显著"重新框成"找到了适用边界""稳定的正向趋势"。换壳不是换结论。
- 不许把数字给出去再补一句"未做检验/仅供参考"——**加限定词不等于过门**。
  那句话不传递可行动信息，只让你事后能说"我提醒过"。也不许把两个单臂数字并排摆着
  让读者自己做减法：语法上不是比较，读者带走的还是那个差，**形式规避比直接违规更坏**。
- 不许拿"用户是专家""他授权了""责任在他"当理由。**你出的那个数会被引用**，
  用户能豁免的是自己的判断，豁免不了这个数是怎么算出来的。
- 不许换个检验、换个指标、换个子集重报。挑赢的那个就是 p-hacking。
- **不许自己手算一个工具没跑过的检验**（符号检验、bootstrap、事后分组）来救门。
  手算的 p 值、手推的样本量与标准误**一律不许写进正文**。
- 不许把"效应方向成立、幅度未确立"拆开说。**方向也是结论**，门 3 没过就是都没有。

**`statement` 说不成立就照抄那句话。** 旁边可以补：效应量点估计、置信区间、
下一步要多少样本（由 `sr_sample_size` 算）、失败样本值得分组看。不可以改写它本身，
也不可以让读者从这一段带走"做出来了"的印象。**哪句话需要哪份证据 →
`references/gates-and-stats.md` 的「声称与证据」表。**
</HARD-GATE>

**门 1 前允许查看原始数据和体检输出，以排查失败；不发布性能分析。** 体检不通过时，
交付诊断及失败原因，不能把这批数据宣称为已验证可用。数据任务无需预注册算法基线；
正式对比须在生成前用 `sr_lock_analysis` 锁主指标与基线，随后把 `prereg_id` 传给生成。
既有数据上新增问题或看过结果后更换指标只能标为探索性，不能补签成正式结论。

1. 查 `sr_capabilities`、可复用数据及预设；系统问题优先 `sr_system_scene`。
   建草稿时显式传入从人话提取的条件；不要假设意图字符串已完整解析。
   `sr_spec_sheet` 是可查看的配置说明，不能代替约定与实际参数核对。
2. 正式大任务先用小试点核对流程与规模；已有明确样本数/预算不得静默替换。
   涉及覆盖、干扰、移动性先探场景。生成后立即 `sr_gate`。
3. 同批数据新增测量量走 `sr_deliver`；拿到代码后运行并核对文件、形状、单位与时延轴。
   不把信道数组倒入对话。改变物理条件才判断是否需要重新生成。
4. 链路对比走内置或外部算法配对入口；系统对比把同数据、同随机种子、同重复流的
   `result_id` 交给 `sr_compare_system_results`。单臂置信区间不是两臂比较判决。
   样本规划读 `references/gates-and-stats.md`；不要问人或手算一个数来救结论。

## 通信口径与当前能力边界

- **只仿下行业务。** 上行业务与上行 IoT 不在范围内，不要向用户提问或报告；
  SRS 只作为下行预编码的信道估计来源。导频干扰目前是解析占位，不能比较场景。
- **结论落在某个物理量上时，先对齐决定它的假设。** `sr_plan` 的 `factor_checklist`
  按影响列出因素与平台取值（下行干扰：发射功率、室内/O2I、邻区负载、站距、统计对象）。
  未建模的因素（全室外、信道层邻区恒满发）必须告诉用户会让结果偏向哪边；
  先让用户写下预期，再用探测对照，偏差大先查假设再正式生成。
- **谱效、业务吞吐、体验速率不同。** 高斯码本谱效不能直接乘带宽冒充业务 Mbps；
  吞吐需经过调制编码、传输块、误块率与资源开销。链路用 `sr_throughput`，
  小区用户竞争、话务、等待和完成时延用系统仿真。不存在通用的“再低百分之几”。
- **满缓冲也能研究边缘用户速率。** 用窗口内每 UE 发送净荷速率的 5% 分位
  `ue_served_p5_mbps`；标准 DRB（数据无线承载）忙期吞吐要等缓冲清空，满缓冲下
  `drb_throughput_rel19_mbps` 为 `None`，不能填零。小包完成时延需有限到达话务。
- **单载波系统基线**为 100 MHz、30 kHz、272 RB（资源块），生成前明确舍去标准表
  273 RB 中的一个。**CA（载波聚合）有独立的显式配置路径**，已包含 20 MHz / 51 RB；
  不能把 CA 支持等同于普通单载波入口接受任意栅格。配置与限制见 system-sim 参考。
- **时域实验要有真实时间轴。** 每 UE 至少八个时间相关快照，并核对
  `sample_interval_s`、位置、速度和运动方向；独立撒点不能冒充连续运动。
  SRS（探测参考信号）周期实验要核对资源分配后实际周期，自动选择周期可能覆盖名义值。
  固定周期比较必须显式控制自适应策略；不能只把 10/20 ms 写进约定。
- **当前系统默认**：`traffic_model="ftp3"`，固定 rank=2，8 次重复，8 个 HARQ
  （混合自动重传）进程，运行时 CQI（信道质量指示）开启，MU 默认关闭；显式开 MU 时
  默认 `mu_precoder="ezf"`。两用户 MU 支持每 UE rank 1–2，包括不等 rank 配对；
  并非任意用户数/任意秩的通用 MU。细节按参考文件与本次 schema 查。
- **本平台 EDF 是 Earliest Drain First（最早排空优先）**，看可发送量与队列水量等因素；
  不是同缩写的 Earliest Deadline First（最早截止时间优先）。人的研究意图涉及
  deadline 时先核对是否真在问本平台这个调度器，不能因缩写相同就声称支持。
- **工程近似要伴随结论。** CQI 平滑系数 0.25 与 1.5 dB 实现损失没有现场标定；
  PDCCH/CCE（控制信道/控制信道单元）未建模。解释吞吐或小包时延时说明影响边界。
- **信道引擎**为 `internal_sim` 与可选 `sionna_rt`；标准 CDL（簇时延线）包含 A–E。
  TDL（抽头时延线）不提供逐径角度，不能拿来验证到达角或空间波束机制。
  硬件默认使用真实子阵及 `pol_h_v + top_to_bottom`；查 default-hardware 参考。
- 测量量保持物理语义：PDP（功率时延谱）不归一化、保留真实时延轴；SRS 返回完整
  协方差和特征值；PMI（预编码矩阵指示）是 Type-I-style 子集近似，不冒充完整标准码本。

## 用结果回答原问题

先给工具支持的判断，再解释“改变条件 → 影响哪个通信环节 → 落到哪个指标”。
例如延长 SRS 周期可能使发射端所知信道更旧；这只是待检验机制，不能替代本次证据。
同时看小区与用户分布、资源利用率、误块率与队列状态，检查数量级、守恒及预期退化关系。
总吞吐较高不能自动说明边缘用户或小包体验更好；单 TTI（传输时间间隔）轨迹只能解释过程。

逐条保留结果 `notes` 的事实和限制，不压成“仅供参考”。报告区分：通信原理解释、
本次观察、过门的比较结论、尚未解释的异常。异常未闭环时不编一个看似合理的物理故事。
区间覆盖话务/ACK 抽样/调度随机性；同一数据集重复不覆盖重新撒点和信道实现的不确定性。
正式跨信道结论还需预先设计独立信道种子；不得事后挑有利种子。

修改物理、随机数或判决机制时按仓库规范运行经典通信基准与相关测试；这些基准不是
现场标定。每批数据核对 provenance，历史数值不能直接当作当前版本锚点。

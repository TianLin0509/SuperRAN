# superran 开发者文档实施计划

> 状态：执行中。本文冻结信息架构、事实来源和验收门；最终交付物为同目录
> `index.html`，它是一份可离线打开、可上传 GitHub Pages 的单文件文档站。

## 1. 目标与读者

文档同时服务四类读者：第一次运行 MCP 的 Agent 开发者、要复核无线物理口径的
算法工程师、扩展系统仿真的实现者，以及负责发布/回归的维护者。正文必须让读者
能从“为什么这样建模”一路追到“哪一个函数实现、怎样验证、边界在哪里”，不能只
做 API 罗列，也不能把历史报告中的数字当成当前事实。

## 2. 交付形态

- 一份自包含 `docs/index.html`；不依赖 CDN、外部字体或网络脚本。
- 外观采用文档站布局：左侧章节树、顶部全文搜索、正文、右侧页内目录、前后页。
- URL hash 表示逻辑页面（如 `#/antenna`、`#/experience`），既满足“一份 HTML”，
  又保留逐页阅读体验和可复制的章节地址。
- 桌面 1440/1024 px、平板 768 px、手机 375 px 均可读；支持键盘、可见焦点、
  `prefers-reduced-motion`、深浅主题与打印。
- 公式内联 KaTeX 资产，同时保留 MathML fallback；图均为可缩放 inline SVG。

## 4. 事实来源优先级

1. 当前 `src/superran/*.py`、`presets/*.yaml` 与函数签名。
2. 当前测试中的不变量和反向哨兵。
3. 项目 `CLAUDE.md` 与 `skills/channel-sim/` 的工作流约束。
4. README 和历史 HTML 仅作线索；若与 1~3 冲突，修正文档或实现，不能照抄。
5. 外部标准/库只解释边界；标准事实要标条款或来源，项目工程选择要明确标“实现选择”。

生成器会从 AST 自动提取模块、公开类/函数、行号、签名、docstring 和 34 个
`sr_*` 工具；从 Skill 文件提取章节；从测试目录提取文件/代码行/静态检查点。
这样新增公开接口但未重建文档时，结构测试会直接失败。

## 6. 发现问题时的处理规则

- 能由当前代码、测试和配置唯一判断的错误：当场修实现/文档并加回归哨兵。
- 会改变产品口径或算法定义的分歧：不擅自拍板，列入“待决策点”，给推荐及影响。
- 历史 HTML 不原地伪装成最新文档；在新文档中标为历史快照，当前事实由生成页承载。
- 所有修复进入最终“本次审计修复”表，包含症状、根因、改动和验证证据。

## 7. 验收门

1. **覆盖门**：42 个源码模块、全部公开顶层类/函数、34 个 `sr_*` 工具、全部 Skill
   reference 和全部测试文件均出现在 HTML；关键算法页均有公式、物理解释、toy example、
   源码入口和限制。
2. **一致性门**：自动计数必须等于当前 AST/文件系统；README、Skill、文档中的工具数、
   Gate 数、默认 RB 与浏览器行为一致。
3. **可执行门**：生成器在 Python 3.10 语法约束下运行；结构测试、公式检查、内部链接检查通过。
4. **视觉门**：用真实 Chromium 在 1440×900、768×1024、375×812 截图/交互检查；无横向
   溢出，导航、搜索、hash、主题、代码复制和移动抽屉可用。
5. **交付门**：`docs/index.html` 存在、UTF-8 首行/中文正常、`</html>` 闭合、离线可打开，
   README 提供入口，Git 状态只包含本任务明确变更与用户原有改动。

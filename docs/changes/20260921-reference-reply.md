# 参考对拍补证：分清计算规则、数据缺口与系统默认

## 1. 改了什么物理机制

- 参考传输块大小计算支持校准重载，低码率大包按 3816 bit 分段；空输入返回 0，避免凭空生成 24 bit。正数半值向上舍入与分支处非单调行为均保留。
- 参考资源反查按 PRB 数递增查找首个够用值，不依赖单调假设，也不以最大 PRB 的结果提前判定不可发送。
- 录入两套完整 29 档曲线码率表，并将有效码率、编码图、冗余版本、码率索引、分块数量和七档阈值输出成可核对的诊断计划。它不返回凭空构造的曲线值。
- SRS 增加显式逐 RB 参考功控，与默认 NR 子载波间隔功控分开。两者均在带宽与偏移叠加后限制总功率，再分到实际活动 RE；数据集接口传递同一配置。

## 2. 为什么

公司回信的完整表和代码片段比首轮摘要更充分，但解释和示例仍互相矛盾：3896 被 Python 舍入算成 3840；MCS28 例子用错 SE=5.25；“MCS0–9 曲线码率都为0.333”与其表不符；切 BG2 不会把小包放大，仍可能落入缺失曲线档。

因此依据表与明确函数片段独立实现，逐项区分源码推导、本地执行与原程序运行。SRS 的参考公式不含子载波间隔项，不能再将标准公式补偿称为参考实现对齐。

## 3. 证据

基线：develop `7d73c8b9067f0c193a32c836ef4c4e841f42a63b`。
输入 Markdown SHA-256：`9ff84a81905a65864f88887a20dfdb12f43f5fc9b7ff0d39e198000a9a177f5f`。

数值锚点：3896 非校准输出3904、校准低码率输出3912；D时隙MCS2、76/77PRB输出3824/3776，3800bit需求在77PRB上限内选择76PRB。MCS28、76/77PRB输出73776/75792。MCS21、200bit进入BG2后仍命中缺失的256QAM档4。CBLER=0.1、两个独立码块合成TBLER=0.19。

功率用线性域参考计算与本机 dB 域实现交叉验证；30kHz、16RB、P0=-96、alpha=0.8、路损110、未触顶时，逐RB口径为4.0412dBm、NR口径为7.0515dBm。它们是同一组显式参数的公式值，不是现场收益。

测试覆盖 `test_physics_contract_extensions.py`、`test_linkadapt.py`、`test_results.py`、`test_physics_invariants.py` 和开发者文档；最终结果以绑定候选提交的审核/合并回执为准。旧版空输入产生24bit的新棘轮必须数值失败。

## 4. 没证明什么

- 回信声称附带原始曲线，但本次收到的Markdown只列部分轴和数据摘要；原始132377字节文件（声明SHA-256为`b91d0a71ee849af13f0962b7b108498ad7608c896dc857b5c8f75ad3945d388b`）未收到，不能校验哈希或构建七档BLER模型。
- 原程序未编译运行；回信中的“运行事实”是Python复现。查表舍入函数定义、完整块大小处理函数、目标场景CalibrationFlag/SFrameFactor/P0/Pmin仍缺。
- 诊断中的查表大小按回信的min(TBS,BG上限)推导，尚不能验证完整CRC、填充、lifting或真实解码器。四个RV字段只是来源数据，不改变系统最多一次重传合同。
- 当前系统仍使用原有28档单码字TBLER模型，参考29档TBS与诊断没有接入调度主循环。不能跨模型混用曲线、重复做CB→TB合成或声称五项全部完成。
- SRS预算仍为诊断能力，不影响信道生成或系统KPI；默认保留NR口径，逐RB对拍需显式选择参考口径。

## 5. 影响哪些 KPI

本次不发布吞吐、覆盖或误块率收益。系统默认路径保持既有曲线合同；新增能力改善对拍的可解释性并阻止空输入、非单调反查和参考面混淆造成的错误。待原始曲线与现场参数补齐后，才能单独实现并验收系统接入。

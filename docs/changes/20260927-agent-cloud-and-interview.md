# 阿里云协作与需求到配置的一致性

## 改了什么物理机制

继承探测与正式生成使用同一有效子阵功率预算的修复。未实现的热点、室内穿透等条件明确披露。
需求访谈保留原话指定的阵型、数量、LOS/NLOS 与功率扫描档位，回答直接进入执行配置。
UMi 推荐使用 10 m 站高；用户显式站高优先。越界扫描、必须但未实现的机制在生成前阻断。
自动选中心站只用于已知编号语义的六边形布局；线性或自定义站点须明确给出服务小区。

## 为什么

默认方案覆盖用户条件，会让“已经跑通”的仿真回答另一个问题。原话、推荐、最终配置必须一致，
无法支持时明确停止。阿里云私有仓库同时成为跨电脑交接的统一来源，独立验证与仿真仍在本机执行。

## 证据

独立物理复核在 2735ac29b5b384be37fc173e7e5d7a3617cacfdd 上通过 15 项专项检查，
包括真实生成的 LOS 标签、实际站高和公开系统入口的自定义站点拒绝。
探测功率棘轮在未修复 e5f6ad20482cb571c4dd4d974785a4ab4b8d29bb 上失败，候选修复后通过。
最终综合候选仍须由独立合并位绑定完整 SHA 执行全量闸门，不能用专项通过替代。

## 没证明什么

未实现机制没有因此变成可用。数据交付与完整算法比较是不同证据层级；通过测试不代表现场标定。
服务器只保存代码与交接记录，不执行无线仿真。成员电脑的实际网络、安装与个人授权仍需逐机接入验证。

## 怎样使用

开发 Agent 从 `INSTALL_AGENT.md`、`AGENTS.md` 与 `.agents/SYNC.md` 开始。
代码经候选分支、独立审核和完整版本回执进入阿里云 develop；GitHub 只保留历史读取。
团队站继续记录进展，历史开工材料保留作档案，不作为新的强制工作步骤。

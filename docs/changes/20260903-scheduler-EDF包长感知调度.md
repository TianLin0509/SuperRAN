# 2026-09-03 调度 — 新增 EDF / qos_pf_edf 包长感知调度（默认不启用），并在 AMC 修正后的基线上重新标定

**来源**：`feat/edf-scheduler` @ `b52f9003d413ab1133c347f7686ea9fa76c63302`，
在 `e5c7c20` 上重新标定为 `feat/edf-recalibrated-20260903`
**风险档**：红　**审核**：双 Reviewer（5 条阻断全修）+ 本次集成重新标定

## 改了什么物理机制

新增 `src/superran/scheduler_edf.py` 内核与两个算法：纯 `edf`（按 TBS/缓冲区比值排序，
小包与好信道优先）和 `qos_pf_edf`（EPF 与 EDF 分量的加权混合），另加硬时延兜底参数
`edf_starvation_hol_ms`。45 个测试。

## 为什么

原有 PF 类调度不感知包的时延预算，小包业务的时延尾部偏大。

## 证据

四条既有调度路径 15 次跨场景运行**逐位不变**。饥饿是**真饥饿**而非记账错误：
被饿死的 UE 有 4-6 MB 积压且 `sched_tti=0`，同一个 UE 在 PF 下能拿到几十次调度。

### 本次重新标定（这是它没能随第一批一起合入的原因）

下行 AMC 链修正（HARQ 进程占用、rank 反馈时序）下修了可达吞吐，导致三个**数值锚点**
失效。隔离实验定位：EDF 单独跑 45/45 通过；叠加 AMC 修正后 42/45；再叠加信道内核
first-party 失败集合完全不变。**元凶是 AMC 修正，不是 EDF 实现有错。**

| 锚点 | 处理 |
|---|---|
| `prb30` 场景实测 PRB 利用率 40.7%，名不副实 | 到达率 4.0 → 3.5 Hz，实测回到 0.2992。**调场景而不是放宽断言** |
| `epf_scale` 轻载读数 0.0246，原断言要求 > 0.3 | 断言改锚在「数量级差异」（`light > 10×sat`）。原附注「轻载下接近平衡」**已被证伪，已删除** |
| `srb_priority_boost` 在原工作点不再改变任何可观测量 | 先实测确认加值本身仍有效（400 Hz / 2000 B / data=4 Hz 三个工作点都有差异），再把场景的 SRB 到达率 200 → 400 Hz |

## 没证明什么

**所有性能数字都是单种子单场景、无置信区间，不能当正式结论。**
未做带置信区间的正式实验。

## 影响哪些 KPI

**合入代码不等于启用，两个算法默认都不启用。** 在 AMC 修正后的基线上重测：

| 指标 | PF | 纯 EDF | 混合（`epf_scale=1e-4`） |
|---|---|---|---|
| Jain 公平性 | 0.4764 | **0.2708** | 0.2788 |
| 零吞吐（饿死）用户 | 0 | **1** | 0 |
| 小包即时服务比 | 0.5235 | 0.5280 | 0.5229 |
| 小区吞吐 Mbps | 364.0 | 423.1 | 429.2 |

**EDF 的收益从旧基线的 +2.3 pp 缩到 +0.45 pp，而公平性代价更大**
（旧基线 Jain 0.4707→0.3032，新基线 0.4764→0.2708）。也就是说
「当前场景不建议启用纯 `edf`」这个结论在修正后的基线上**比原来更成立**。
要用请用标定后的 `qos_pf_edf` 混合模式。

硬兜底 `edf_starvation_hol_ms` 是钝器：200 ms 门限下饿死归零，代价是吞吐相对纯 EDF
−23.8%、小包即时掉到 0.5161（比 PF 基线还低）。标定 `edf_mixed_epf_scale` 的混合模式
在每个轴上都优于它，**硬兜底保留但默认关闭**。

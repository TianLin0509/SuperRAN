# 2026-09-27 提问流程复审整合 — 原话、扫描档位和实际服务小区对齐

本次基于开发主干 `94557607078784ca9cd1540be7f7c47b29fb1b69`，整合第三轮候选的有效修复，并解决第四轮发现的输入理解问题。不是把旧候选整份覆盖回主干；已有的视距/非视距识别、部署站高和用户显式取值保护均保留。

## 改了什么物理机制

信道与调度公式不变。变化发生在实验输入和评估对象的选择：

- 扫描列表按物理量归属。功率 33/53 dBm 后的 20 MHz 带宽不会变成第三档功率；带宽 0.02/0.1 GHz 按共享单位换算为 20/100 MHz，也不会把 0.1 GHz 当成载频。原话、后续回答和执行前检查共用同一套解析、量纲及范围合同。
- 否定只修饰紧邻的要求。“不比算法，要考虑室内穿透”仍要求室内模型；“不是最早排空，是最早截止”仍要求截止调度；“不能忽略室内穿透”是正要求。这些未实现的机制继续阻断，不能被“按推荐跑”消除。
- 自动选择服务小区时，用生成信道的同一套站址重建方法寻找几何中心。线形和自定义站址都根据位置判断；中心站没有足够用户而选边缘站时明确披露。无法重建或含非有限坐标时要求显式指定小区。
- 预设不再推荐已删除的上行 IoT、导频 NMSE 下限或占位测量的“净效应”。解析占位和不可用于导频方案比较的边界直接显示在预设里。

## 为什么

实验必须回答用户提出的问题。把带宽数字串入功率列表、把否定的调度算法当成用户要求，或把线形网络的边缘站叫成中心站，都会让工具顺利运行却回答另一个问题。

这一整波流程重做还包括：已说条件直接写入草稿；区分交付数据、刻画一个量、扫描条件和比较方法；每轮最多问三个依赖已满足的问题；记录平台假设和未实现边界；用信道层敏感度探测帮助决定先问什么。本次整合保留这些已在主干的能力，并补齐上述接口一致性。

## 证据

工作位将原二轮 11 条、三轮 8 条、四轮 4 条验收作为外部回归复测，23/23 通过。仓库端到端测试新增反向否定、跨句、共享单位、混合频率单位、量纲错误拒收和负载范围合同；几何中心选择另有物理不变量测试，兼容未修复主干的旧调用入口，便于独立审核反证。

相关验证采用逐文件矩阵：端到端、MCP 服务、射线追踪决策、干扰、开发者指南、系统工具和物理不变量。首次 6/7 通过；新加的端到端断言误读输出路径而抛出 KeyError。修正断言路径后，端到端与重建指南复跑 2/2 通过，七个相关文件均取得通过结果；首跑日志保留。完整全量和最终提交绑定以独立合并位报告为准。

原来的两条“线形/自定义拓扑一律拒绝自动选择”断言被实际几何选择、回退披露和无法重建时拒绝的断言替代：这是从不支持到明确支持的行为变化，没有放宽数值判据。

## 没证明什么

自然语言仍使用规则识别，不代表理解任意表达。敏感度仍主要衡量信道层 IoT、SIR、SINR，未新增系统级速率/时延敏感度。默认 46 dBm 没有现场标定；不可用的部分带宽 SRS 跳频预设没有在本任务中实现。工作位只跑相关集，全量和真实端到端由独立合并位完成；没有把模型扮演用户当成人类可用性评估。

## 影响哪些 KPI

不宣称性能收益。正确保留扫描档位决定结果对应哪个条件；正确选择服务小区决定评估的是中心站还是邻区不完整的边缘站。吞吐、边缘速率和 SINR 的具体变化量需在最终配置上重新实测。

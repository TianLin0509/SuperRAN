## 改了什么物理机制

| 环节 | 2026-09-07 至 09-09 的核心变化 |
|---|---|
| 多用户多天线（MU-MIMO） | 9 月 7 日已通过 PR #26 同步：配对默认采用 EZF，伙伴按配对后谱效排序；每用户 1～2 层，允许异层数配对，功率按实际层数分摊。本批继续接通宽带单用户波束权相关矩阵和可选权计算方法，固定先逐 RB 算相关性、再按 RBG 与宽带聚合的顺序。 |
| 信道的空间与时间一致性 | 统一垂直相位与自上而下的阵列端口位置；删除随样本编号周期变化的人造 UE 空间混合；同一 UE 复用散射体并推进绝对时间，跨样本连续演化。 |
| 信道估计与可用时刻 | 将最小二乘导频观测、频域维纳估计、跳频顺序保持及跳频拼接接入实际生成链。逐资源块组（RBG）保留测量时刻、新鲜度与最近一次真实探测范围；没有新机会时保持旧状态。已含跳频时间历史的数据不再重复叠加跳频老化。 |
| 探测参考信号（SRS）污染 | 新增“干扰 UE → 本站”的上行交叉链路。污染按真实导频资源碰撞和实际探测频段生成，空资源不产生干扰发射；切换后重配资源。交叉链路、资源占用和时序贯通生成、存储与加载。 |
| 吞吐与业务时段 | 并列提供首传净荷、发送侧 MAC 吞吐、接收侧 MAC 吞吐。接收侧按确认反馈到达基站的时刻归属测量窗，并单列窗前发送、窗内确认的贡献。新增业务忙期 Head/Body/Tail 分段及字节、墙钟时间对账。 |
| 统计判决 | 配对重复次数不超过 5 时，明确返回样本量不足、无法判显著的原因，不通过切换检验放行。 |

## 为什么

此前若干接口名与实际行为不一致：多个估计器档位走同一条加噪路径；缺少干扰 UE 到受害基站的上行信道，已有导频接收机无法获得正确输入；信道跨样本不连续或人为混合，使老化与秩变化混入生成器误差。

调度侧需要知道一份测量究竟何时发生、哪些 RBG 被真正探测，不能把“最近一次测量”误当成“本次出现新测量”。吞吐侧则必须区分队列发出字节、空口重复发送字节与确认收到字节，避免把不同统计口径当成同一性能指标。

## 没证明什么

- 本批次没有发布现场吞吐提升百分比，也未证明全部算法与 AirView 数值完全一致。回归通过说明已覆盖的合同与反例成立，不代替现场标定。
- 上行交叉链路采用等 UE 发射功率的工程假设，未建模完整上行功率控制。估计主链的 RB 粒度等效观测与独立 RE 级波形接收机必须区分，不能把前者写成全链路逐 RE 仿真。
- 连续轨迹上的相邻样本相关，不是新增的独立信道实现。重复运行的置信区间也不自动覆盖信道实现本身的不确定度。
- 测量窗前后的反馈跨界会影响接收侧与发送侧计数之间的大小关系，不能宣称任意短窗下接收吞吐都小于首传净荷吞吐。
- 本次改变了信道、估计和配对决策口径。此前数值保留为其原始版本的历史结果；不能与本批新结果直接串成趋势或复用为当前性能基线，比较需在同版本、同数据与同统计口径下重跑。

## 影响哪些 KPI

| 指标 | 影响 |
|---|---|
| 信道估计误差、CSI 年龄和波束更新次数 | 估计器与测量时序改变，需重新生成和评估；本批不发布统一增益。 |
| SU/MU 比例、rank、MCS、首传误块率 | 信道、波束权、相关性与可用测量共同影响决策，变化方向随场景而定。 |
| 小区及用户吞吐、业务完成时延 | 受实际链路和调度变化影响，量级未在本变更说明中测量。 |
| 发送侧 / 接收侧 MAC 吞吐、Head/Body/Tail 速率 | 新增并明确分母、计数事件与窗口边界，应按各自定义读取。 |
| 配对比较结论 | 小样本被明确拦截；这是证据充分性的变化，不是无线性能退化。 |

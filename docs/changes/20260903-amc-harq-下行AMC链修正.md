## 改了什么物理机制

下行链路自适应这条链上的四处因果错误：

1. **HARQ 进程占用**：首传的 ACK 此前不占用单 HARQ 进程，导致反馈还没回来、同一个 UE
   就能连续发新 TB。现在 ACK 与 NACK 一样占用进程，终次反馈延迟释放。
2. **rank 判决时序**：rank 快速回退在发送当时就读到了尚未回传的 ACK/NACK。现在只在
   反馈真正到达后才消费。
3. **MU 准入**：capacity 模式此前不检查完整 pair 图，且用叠加 OLLA 之前的 MCS 做准入。
   现在按完整 pair 表记账，并用实际发送的 MCS 判断。
4. **switch_rule 默认值**在不同入口不一致，已统一。

## 为什么

这四条都属于「用到了当时物理上还拿不到的信息」。仿真会因此系统性高估下行吞吐，
而且偏差随反馈时延增大——正是最需要它准的场景最不准。

## 证据

新增 HARQ 因果反例测试：**在旧实现上失败、在新实现上通过**。`tests/test_system.py`
新增大量断言；相邻物理回归通过。三轮独立审核。集成后主仓库全量 pytest 通过。

## 没证明什么

不等于现场完全等价。15 dB BF 惩罚、CQI floor/reset、现场 OLLA 参数仍是**明确的工程近似**，
未与现网校准。也不等于性能收益——修正后吞吐更低但更可信，这不是「优化」。

## 影响哪些 KPI

下行吞吐、频谱效率方向性下修；MU 配对比例改变。**已实测到的一个连带影响**：
既有场景的工作点会移动——EDF 分支标定的「30% PRB 工作点」在本修正之后实测为 40.7%。
任何依赖绝对工作点数值的标定都需要在本修正之后重做。

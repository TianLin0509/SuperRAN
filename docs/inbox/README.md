# 公司审阅收件箱

公司 Agent 写的审阅报告放这里。你只要把文件复制进来，然后对本地 Agent 说：

```
读 C:\Vibe\Wireless\SuperRAN\.agents\AUTHOR.md 按它工作。
任务：处理 docs\inbox 里的公司审阅报告
```

## 为什么这个目录不进 git

本目录除了这份 README 之外**都被 gitignore**，不会被推到公开仓库。
公司报告即使按 `.agents/COMPANY.md` 的规矩写过，也不必要地进入公开历史。
本地 Agent 读完之后，把**修复本身**提成正常的 PR，报告留在本地就行。

## 本地 Agent 拿到报告后要做什么

1. **先核对基线**：报告开头抄了 zip 里 `CHANGELOG.md` 的最新一条。
   对照当前 `develop`，判断它看的版本落后多少。落后太多的问题可能已经修过了。
2. **逐条验证，不要照单全收**。公司 Agent 看的是快照，而且没法运行代码。
   每条都要在当前代码上确认问题真的存在，再动手。
3. **按报告里的「怎么验证」写测试**：先让它在现有代码上失败，再修到通过。
   这就是 `.agents/AUTHOR.md` 里的棘轮规则。
4. **一条问题一个提交**，别把几条打包。
5. 报告里"不确定的地方"那一节的内容，**先验证再说**，不确认就不要改。

## 给公司 Agent 的东西

`.agents/COMPANY.md` —— 连同 GitHub 下载的 zip 一起给它。

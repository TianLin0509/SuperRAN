四、可信度是怎么保证的

三道门，各守一个阶段。体检管的是"信道对不对"， 但信道对了结论照样可以是错的——所以后面还有两道。

3GPP 官方的校准口径

业界判断信道生成得对不对，不看曲线好不好看，而是按 TR 38.901 §7.8 规定的口径把指定的统计量算出来，跟各参与方提交给 3GPP 的参考曲线对。 sr_calibrate 按条款出数：

条款指标说明
§7.8.1 指标1
§7.8.2 指标1		耦合损耗 CDF（服务小区） = 发射功率 − 接收功率。串联检验路损模型 + 天线方向图 + 小区选择，任一环错了整条曲线平移
§7.8.1 指标2
§7.8.2 指标2		几何量 CDF，含噪与不含噪两条 不含噪那条即宽带 SIR。查"干扰进没进计算"最直接的手段
§7.8.2 指标3时延扩展 + 角度扩展 ASD/ASA/ZSD/ZSA 角度扩展按 Annex A.1 圆周定义，不是普通标准差——普通标准差在角度绕回 0/360° 时会算出荒谬的大值
§7.8.2 指标4PRB 奇异值：最大、次大、比值三条 CDF 标准原话是"PRB 内平均协方差矩阵的特征值"，10log10 尺度，t=0。比值那条尺度无关，是三条里最稳的判据

参考曲线在 3GPP 文稿 R1-165974（大尺度）、R1-165975（全校准）、 R1-1909704（InF）里。本工具只出数不判决，判决在门 1。 不适用的项会说明原因——比如 CDL 的时延角度是查表固定值，它的 CDF 是退化的， 拿去比参考曲线没有意义。

它真的抓到过问题

CDL 剖面表本身抄错了。ChannelHub 的 CDL_A/B/C 三张表标着 "TS 38.901 Table 7.7.1-x"，时延与功率两列对得上，但角度列从中段起与标准不符。 CDL-C 有 23/24 簇有出入，这些簇占总功率 93.8%； 按 Annex A.1 算出来 ASA 偏 14.5°、ASD 偏 7.1°。

角度错了不会报错，只会让空间相关性、波束赋形增益、到达角估计 这类结论安静地偏掉——而这正是谱效仿真最依赖的部分。现在 superran 启动时会把 逐字核对过的标准表灌回仿真器（不改 ChannelHub 一行源码，替换的是 get_cdl_profile 读的那个字典），门 1 里逐簇复核。

为了不冤枉别人，标准表是手抄一遍 + 从 PDF 机械解析一遍 两条独立路径核对过的，两者逐项一致才下的结论。

多小区跑了半天，干扰根本没进 SINR。ChannelHub 只在配置里给了 bs_panel（面板排布）时才建 DFT 码本，而几何 SINR 依赖这个码本。 拿不到码本时它走兜底：sir_dB = 49.9（刚好卡在 ±50 dB 契约边界内的哨兵值）、 sinr_dB = snr_dB——这条路径不报错、不告警。

结果是配了 21 个小区、报出来的"SINR"却是单小区热噪声 SNR。 实测同一配置修复前后：SINR 中位数 35.7 dB → 18.1 dB，差 17 dB。 在此之前所有多小区数据集的干扰类结论都不成立。

现在生成时由 num_bs_tx_ant 自动推导面板排布， 门 1 里用"SINR 是否逐点等于 SNR"和"SIR 是否恒为 49.9"两条判据复查。 这正是 3GPP 那条"geometry with and without white noise"要出两条曲线的用意。

配置矛盾：视距场景配非视距剖面。 scenario="UMa_LOS" + channel_model="CDL-C" 跑得出结果， 但路损按视距算、多径按非视距的强散射剖面走，时延扩展偏离标称值 4.4 倍， 那批数据既不像视距也不像非视距。

小区数被悄悄改掉。六边形栅格按环数展开，站数只能是 1/7/19， 配 2 站会实际生成 7 站。而 ChannelHub 的 describe() 只回显配置值—— 用户以为跑的是 6 小区，实际是 21 小区，干扰环境完全不同。

现在生成后会自动对比配置值与实际值，不一致就报出来， 并提示改用线性布站或自定义坐标。

开发这套检查时，我自己先被误导了两次。都记进了项目规范：

① 路损比对必须复刻仿真器的公式选择逻辑—— scenario 已是 _LOS 时所有链路都用 LOS 公式，不看 is_los。 错一层会看到 −28 dB 的假偏差，差点误判 ChannelHub 有 bug。

② 38.901 的 LOS 公式在 d<168 m 处必然低于自由空间（最多 4.45 dB）。 它是拟合式不是物理下界；含阴影后过半样本低于自由空间更是常态。 判据只能用去阴影后的公式值。

这几个都属于"跑得出结果、数值看着正常、图也画得出来，但结论是错的"。 蒙特卡洛仿真最怕的就是这种——所以体检不是可选项。

门 2 与门 3：信道对了，结论仍可能是错的

真正让仿真结论翻车的，多数不是信道：

门拦什么为什么致命
门 2

两臂必须跑在同一批信道上。共同的路损、撒点、衰落起伏被差分抵消， 剩下的才是方案本身的差别——配对设计所需样本数常比非配对少一个数量级。

样本数是算出来的，不是问出来的

N ≥ ( (1.96 + 0.84) · σ_d / Δ )²

σ_d 是逐样本差值的标准差，Δ 是想检出的最小效应。 流程：先跑 20 个样本试点量 σ_d，再算正式样本数。

反解更该先看一眼：给定样本数，算出最小可检出效应。 它比期望增益还大时，这次实验无论跑出什么结果都不足以下结论—— 该加样本，而不是跑完再解释。

实测互为反解：σ_d = 0.83、要检出 Δ = 0.30 → 需要 61 个样本； 反过来 n = 60 时最小可检出 0.3002。效应减半，样本数变四倍（平方关系）。

问用户"你想跑多少次蒙特卡洛"，是把自己该做的功课推回去。 这一条是从 superpowers 那句 prevent agents from delegating prioritization back to humans 学来的。

五、谱效链路的设计

刻意拆成三段，每段都能换成你自己的算法再接回来。

预编码 W→ 有效信道 Heff = WH·H→ 后处理 SINR→ 谱效

为什么不直接给一个"谱效"数字。它取决于三个独立选择：用什么预编码、 用什么接收机、算不算干扰。同一批信道，SVD 和 DFT 波束能差 3 倍。 摊开才对比得清楚——这也正是"你的方法要跟什么比"的落点。

可选取值
预编码svd 理论上界 · svd_wideband 全带共用 · type1 38.214 码本 · dft 波束 · mrt · identity
接收机mmse · zf · mrc，口径写在函数文档里
干扰传 h_interferers 则计入，得到真正的 SINR 而非 SNR

接收机对比的一个物理细节。SVD 预编码后有效信道已对角化，层间干扰为零， 三种接收机完全等价（实测都是 27.191）——这是正确的。 换成 identity 预编码保留层间干扰后差异才显现：

MMSE 7.383 ＞ ZF 2.685 ＞ MRC 2.008 bit/s/Hz，完全符合理论。

六、物理层工具箱

ChannelHub 里已按 38.211/38.213/38.214 实现的模块，主要用来当基线。

from superran import physical as ph

ph.nr_rb_count(100e6, 30000)      # 273（标准表，不是简单除法）
ph.tdd_pattern_info("DDDSU")      # 周期 5 时隙 / 5 ms，特殊时隙 10 DL + 2 UL 符号
ph.srs_config(273, b_srs=1)       # 跳频周期 17，每跳 16 RB，只覆盖 6% 带宽
ph.zadoff_chu(25, 139)            # 恒模误差 4.1e-08，自相关峰旁比 151 dB
ph.ssb_sequences(42)              # PSS / SSS / PBCH-DMRS
ph.dft_codebook(8, 4, 2)          # CSI-RS 波束码本 [512, 64]
ph.estimate_channel(h, method="mmse", tau_rms_s=363e-9)   # LS / MMSE 基线
ph.project_interference(...)      # 干扰投影——不投影会高估干扰

信道估计基线（SNR=20 dB）。导频间隔要和相干带宽匹配， 间隔过大时插值误差主导，提高信噪比也没用：

导频间隔LSMMSE
2−14.04 dB−16.75 dB
8+1.24 dB （已失效）−5.76 dB （仍可用）

MMSE 利用了频域相关性，稀疏导频下优势明显。

八、已知约束

  • 信噪比不能直接设定——它由路损、发射功率和撒点位置决定。要求特定区间时走拒绝采样。
  • 视距比例由几何决定，不是选 CDL-D 就能得到视距信道。改站间距才有效（实测 200 m→0.46、800 m→0.13）。
  • 六边形栅格的站数只能是 1/7/19。需要精确站数用线性布站或自定义坐标。
  • 射线追踪拿不到逐径几何——ChannelHub 尚未导出 Sionna 的 Paths 对象， 所以 ds.paths() 会报错而不是返回假角度。
  • 时延扩展的频域估计有固有误差，实测比值 0.8~1.0，仅作数量级检查。
  • QuaDRiGa 未纳入，需要 MATLAB/Octave。

# 同步 GitHub（只在维护者明确说"同步 GitHub"时执行）

日常迭代**不碰远端**。这一步是把攒了一批的本地改动整理成一次干净的对外提交。

## 步骤

1. 列出本批次自上次同步以来进入本地 `develop` 的提交，逐条确认都已通过审核。
2. 为每条改动在 `docs/changes/` 写一份短文档（模板见该目录 README），文件名
   `YYYYMMDD-<模块>-<一句话>.md`。已有的不重写。
3. 更新 `CHANGELOG.md` 顶部：日期 + 一行摘要 + 指向 `docs/changes/` 的链接。
4. 按风险档跑回归：红档跑该模块 + 相邻物理测试；黄档跑相关测试；绿档跑文档检查。
   **保留真实退出码，失败就停下报告，不许重试掩盖。**
5. 推送分支并建 PR。PR 正文必须包含：改了哪个无线环节、证据、**没证明什么**、
   Author 报告与 Reviewer 结论的路径。
6. 把准确的分支名、完整 SHA、PR 编号给维护者。**远端合并由维护者批准，Agent 不许自己合。**

## 内网 Agent 回路（单向）

给它的合同是 `.agents/COMPANY.md`，连同 GitHub 下载的 zip 一起发。
它的报告放 `docs/inbox/`（该目录已 gitignore，不进公开仓库）。

内网 Agent 拿到的是 zip 快照，它给回来的 patch 大概率打不上当前 HEAD。所以：

- 内网 Agent **只产出问题清单**：文件 + 行号 + 物理论据 + 最强反例。
- **不接受 patch、不做冲突合并。**
- 本地 Agent 按清单当作新任务重新实现，走正常的 Author → Reviewer 流程。
